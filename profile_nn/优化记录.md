# ProfileNet 模型优化记录

> 日期：2026-06-03  
> 触发原因：远程服务器 ONETWO 验证时发现模型拟合效果不够好

---

## 一、问题诊断

### 1.1 优化前模型状态

| 指标 | Te | ne | Ti |
|------|-----|-----|-----|
| 真实样本数 | 151 | 82 | 56 |
| 合成样本数 | 500 | 500 | 500 |
| 合成/真实比 | 3.3:1 | **6:1** | **9:1** |
| 验证 MSE | 0.360 | 0.463 | 0.601 |
| 脏数据文件 | 2（负值） | 1（越界） | 0 |
| 训练参数 | 58,304 | 58,304 | 132,736 |

### 1.2 根因分析

1. **合成数据淹没真实分布**：合成数据（参数化 mtanh 剖面 + 纯高斯噪声）与真实 EAST 数据分布不同。尤其 ne（6:1）和 Ti（9:1）模型主要学的是合成模式，在真实 EAST 数据上泛化差。

2. **脏数据**：3 个文件包含负值/越界的异常数据，污染训练集：
   - `148100_Te_3d99000.npz` — Te Y min = -1.84 keV（物理不可能）
   - `149000_Te_4d11000.npz` — Te Y min = -11.13 keV
   - `73100_ne_1d10000.npz` — ne X_val max = 21.5 ×10¹⁹ m⁻³（越界）

3. **推理无单调性保护**：只有 Ti 有 PCHIP 后处理，Te 和 ne 直接输出 NN 预测值，可能出现不合理上翘段。

4. **超参数可优化**：训练 LR 1e-3 偏高、smoothness 权重偏低、对样本量最小的 Ti 约束不足。

## 二、优化方案

### 2.1 数据清洗（P0 — 立即执行）

#### 删除脏数据

```bash
rm profile_nn_data/148100_Te_3d99000.npz
rm profile_nn_data/149000_Te_4d11000.npz
rm profile_nn_data/73100_ne_1d10000.npz
```

#### 削减合成数据（500 → 150/类）

```bash
python -c "
import os, glob
for dt in ['Te','ne','Ti']:
    syn = sorted(glob.glob(f'profile_nn_data/synthetic_{dt}_*.npz'))
    for f in syn[150:]:
        os.remove(f)
"
```

**理由**：合成数据和真实数据的比例从 3:1~9:1 调整到 ~1:1，让模型更多地从真实 EAST 数据中学习。合成数据仅用于提供基础剖面形状先验。

### 2.2 推理后处理增强（P1）

在 `profile_nn/infer.py` 的 `nn_fit_te()` 和 `nn_fit_ne()` 中添加 PCHIP 单调性强制后处理：

```python
# 在返回前添加
from scipy.interpolate import PchipInterpolator
try:
    pchip = PchipInterpolator(rho_201, -y_201)
    y_201 = np.maximum(-pchip(rho_201), 0.005)
except Exception:
    pass
```

**理由**：Ti 原有此保护，Te/ne 缺失。PCHIP 作为安全网确保输出剖面的单调递减性（物理约束），不依赖模型自身保证。

### 2.3 超参数调优（P1 — 重新训练）

| 参数 | 优化前 | Te 优化后 | ne 优化后 | Ti 优化后 | 调整原因 |
|------|--------|-----------|-----------|-----------|---------|
| `--lr` | 1e-3 | 5e-4 | 5e-4 | 5e-4 | 更低学习率 → 更平稳收敛 |
| `--batch-size` | 64 | 32 | 32 | 32 | 小批量增加梯度噪声，抑制过拟合 |
| `--epochs` | 500 | 600 | 800 | 800 | 低 lr 需要更多步收敛 |
| `--w-mono` | 0.1 | 0.15 | 0.2 | 0.2 | 增强单调约束 |
| `--w-bdy` | 0.5 | 0.5 | 0.5 | **1.0** | Ti 数据最稀疏，磁轴约束需加强 |
| `--w-smooth` | 0.05 | 0.08 | 0.1 | **0.2** | Ti 样本极少（56），平滑正则防止锯齿 |

Ti 的训练约束最激进，因为：
- 真实样本仅 56 个，最容易过拟合
- TXCS 诊断点极少（3-15 通道），输入信息极度稀疏
- 需要最强的物理先验（smoothness + boundary）来弥补数据不足

### 2.4 训练命令

```bash
# Te
python -m profile_nn.train --data ./profile_nn_data --datatype Te \
    --epochs 600 --lr 5e-4 --batch-size 32 \
    --w-mono 0.15 --w-bdy 0.5 --w-smooth 0.08 \
    --output ./profile_nn_models

# ne
python -m profile_nn.train --data ./profile_nn_data --datatype ne \
    --epochs 800 --lr 5e-4 --batch-size 32 \
    --w-mono 0.2 --w-bdy 0.5 --w-smooth 0.1 \
    --output ./profile_nn_models

# Ti
python -m profile_nn.train --data ./profile_nn_data --datatype Ti \
    --epochs 800 --lr 5e-4 --batch-size 32 \
    --w-mono 0.2 --w-bdy 1.0 --w-smooth 0.2 \
    --output ./profile_nn_models
```

## 七、推理单调性保证增强（2026-06-03）

### 问题

PCHIP 后处理无法消除所有类型的非单调段（PCHIP 保证分段单调但离散采样点可能存在 <0.001 的微小违反）。

### 修复

在 `infer.py` 中，PCHIP 后追加 `np.minimum.accumulate`：

```python
# 从左到右扫描，将任何上翘点裁剪到前一有效值
te_201 = np.minimum.accumulate(te_201)
```

三模型（Te/ne/Ti）均已应用，保证输出剖面**严格非递增**。物理影响极小（仅修正 <0.001 量级的数值伪影）。

## 九、V2 架构增强与损失函数优化（2026-06-25）

### 9.1 问题

V1 模型（第八节）在真实 EAST 数据上存在以下问题：
- **台基区域拟合差**：pedestal 陡峭梯度处 MSE 显著偏高
- **芯部峰值度不足**：预测 Te(ρ=0)/Te(ρ=0.5) ≈ 1.5，标签 ≈ 2.3
- **边缘预测趋近于零**：部分 Case 边缘 Te < 0.01 keV，可能导致 ONETWO 数值崩溃
- **早停过早**：Te@201ep, Ti@111ep，模型未充分收敛

### 9.2 架构增强

#### Fourier 特征编码（CoordDecoder）

参考 NeRF 位置编码，在 `CoordDecoder` 中将 1D ρ 坐标投影到高频空间：

```python
# 32 频率 Fourier 特征: ρ → [ρ, sin(2π·B·ρ), cos(2π·B·ρ)]
# input_dim: 1 → 65 (1 raw + 32*2 Fourier)
self.register_buffer('fourier_B', torch.randn(1, n_freq) * 2.0)
```

**效果**：MLP 能表示台基处 ρ≈0.9 的高频陡峭梯度，线性组合即可表达尖锐过渡。

#### PerChannelSoftplus

替换标准 `F.softplus` 为可学习的逐通道 Softplus：

```python
class PerChannelSoftplus(nn.Module):
    def __init__(self, num_channels=201, beta_init=2.0):
        self.raw_beta = nn.Parameter(...)  # 每 ρ 位置独立 β
    def forward(self, x):
        beta = F.softplus(self.raw_beta).clamp(0.5, 20.0)
        return F.softplus(x * beta) / beta
```

**效果**：芯部平坦区域用低 β（接近线性），台基区域用高 β（陡峭过渡），模型自适应学习。

### 9.3 损失函数增强

#### 区域加权 MSE

```python
# 芯部 (ρ < 0.30): weight = 3.0   → 促进峰值度
# 台基 (ρ > 0.82): weight = 25.0  → 捕捉陡峭梯度
# 中间区域: weight = 1.0
weights = weights / weights.mean()  # 保持总 MSE 尺度不变
```

#### 对数空间损失

```python
# 对低值区域的相对误差更敏感
# 防止 Te=0.05→0.01 keV 这种 80% 相对误差被 MSE 忽略
loss_log = ((log(y_pred + ε) - log(y_true + ε))²).mean()
w_log = 0.1
```

#### 权重调整

| 参数 | V1 | V2 | 说明 |
|------|-----|-----|------|
| w_mono | 0.1-0.2 | **0.05** | 降低：PerChannelSoftplus + PCHIP 已保证单调性 |
| w_bdy | 0.5-1.0 | **0.05** | 降低：Fourier 特征能自然学习平滑边界 |
| w_smooth | 0.05-0.2 | **0.01** | 降低：减少过度约束 |
| pedestal_weight | — | **25.0** | 新增：台基区域加权 |
| core_weight | — | **3.0** | 新增：芯部区域加权 |
| w_log | — | **0.1** | 新增：对数空间损失 |

### 9.4 推理后处理

边缘安全地板（防止 ONETWO 数值崩溃）：

```python
te_201 = np.maximum(te_201, 0.005)   # 绝对下界
te_201 = np.minimum.accumulate(te_201)  # 强制单调递减
```

三模型（Te/ne/Ti）均已应用，所有 4 个推理脚本（infer.py, infer_lstm.py, infer_transformer.py, cnn_baseline.py）同步更新。

### 9.5 多模型架构

引入 3 个对照组架构，与 ProfileNet（SetEncoder）对比：

| 模型 | 编码器 | 解码器 | 参数量 |
|------|--------|--------|--------|
| ProfileNet | PointNet SetEncoder (置换不变) | CoordDecoder | 58K |
| LSTM | BiLSTM(hidden=64, 2层) | CoordDecoder | 76K |
| Transformer | Self-Attention(4-head, 2层) | CoordDecoder | 127K |
| CNN-1D | Pure ResNet (无 DeepONet 组件) | Conv1d Decoder | 66K |

> LSTM 和 Transformer 共享 CoordDecoder + PhysicsConstrainedLoss，仅编码器不同。CNN 是完全独立的纯 ResNet 架构，作为对照证明 DeepONet 分支-主干模式的优势。

### 9.6 V2 训练结果

| 模型 | Te Val MSE | ne Val MSE | Ti Val MSE |
|------|-----------|-----------|-----------|
| LSTM | **0.325** | **0.358** | 0.152 |
| Transformer | 0.367 | 0.373 | 0.162 |
| ProfileNet | 0.370 | 0.376 | **0.149** |
| CNN-1D | 0.806 | 1.056 | 0.286 |

> 部署建议: Te→LSTM, ne→LSTM, Ti→ProfileNet

### 9.7 剩余问题

- **根因**: 训练集以 L 模为主导（ped_width 0.02-0.08 太宽），H 模窄台基数据不足

## 十一、真实 H 模数据获取与 V4 训练（2026-06-25）

### 11.1 关键发现

扫描全部 161 个炮号的 H98（能量约束因子）数据后发现：

| 分类 | 数量 | 说明 |
|------|------|------|
| H 模炮号 (H98_max > 1) | **144** | 88% 的炮号有过 H 模时段 |
| L 模炮号 (H98_max ≤ 1) | 6 | 仅 6 个纯 L 模 |
| H98 不可用 | 11 | MDSplus 树不完整 |

**但数据集中只有 5/2781 个样本来自 H 模时间点（0.4%）！**

**这就是模型无法拟合 H 模台基的根本原因。**

## 十三、ONETWO ZFIT 兼容性问题（2026-07-06）

### 13.1 现象

在部署服务器上运行 ONETWO 流水线（炮号 156005，6 个时间点），NN 版本（ProfileNet / LSTM / CNN / Transformer）全线以 **exit code 91** 失败，`_outone` 末尾报错：

```
FATAL ERROR in ZFIT
you have exceeded temperature range for curve fits
tkev =
```

同时，mtanh 版本**同样有 5/6 个时间点失败**（相同错误），仅 009.01780s 一个时间点成功。

### 13.2 根因分析

**不是 NN 剖面的问题，是 ONETWO 内部 ZFIT 子程序与 EAST 参数范围的兼容性问题。**

ZFIT 是 ONETWO 的 Fortran 子程序，负责 Zeff 辐射/原子物理速率拟合（碳杂质线辐射）。它内部有原子数据表（ADAS 等），对输入温度有有效范围限制。

对比 009.01780s 的成功与失败案例：

| 版本 | TEIN core | TIIN core | TIIN edge | 结果 |
|------|-----------|-----------|-----------|------|
| mtanh | 4.09 keV（错误单位¹） | 0.877 keV | 0.050 keV | ✅ 成功 |
| NN | 3.03 keV | 0.827 keV | 0.077 keV | ❌ exit 91 |

> ¹ **已知的 mtanh 单位 bug**：`onetwo_output.py` 将 Te 以 keV 写入 TEIN（ONETWO 期望 eV），导致 ONETWO 误读为 4.09 eV（实际应为 4090 eV）。这一 bug 反而让 ZFIT 走了极低温简化分支（Te ≈ 0.004 keV），绕过了正常温度路径的表格越界检查。

**关键发现**：NN 版本的 TIIN edge（0.077 keV）实际上**高于** mtanh 版本（0.050 keV），但 NN 仍然失败。说明 ZFIT 的判据不仅依赖 Ti 边缘值，还与 Te（正确单位时为 3 keV）的联合参数域有关。NN 以正确的物理单位（eV）传递剖面数据，反而触发了模板面向 CFETR 高温工况（Te > 5 keV, Ti > 0.5 keV）设定的 ZFIT 表格边界检查。

### 13.3 证据链

1. **mtanh 与 NN 同样失败**：004-008 五个时间点，两个版本都报 ZFIT 错误，排除 NN 特有的问题
2. **009 mtanh 成功的特殊性**：单位 bug 导致 Te 被 ZFIT 当作 ~0.004 keV 处理，走简化分支通过
3. **009 NN 失败**：Te=3034 eV（正确单位），触发 ZFIT 完整路径的表格越界
4. **所有 6 个时间点的 NN 拟合剖面图均正常生成**：说明剖面质量本身没有问题

### 13.4 影响范围

- **核心功能（NN 剖面拟合）**：不受影响。拟合结果正常、剖面图正常、LHW 功率/电流计算正常
- **下游验证（ONETWO 输运）**：受阻，无法通过完整的 ONETWO 链路验证 NN 剖面在输运计算中的表现
- **中期答辩**：可将此作为"已实现的集成链路，受限于 ONETWO 模板配置"来表述；NN 拟合的剖面图和指标对比已足够支撑核心论述

### 13.5 可能的修复方向

1. **修改 `inone_template` 中的 Zeff/ZFIT 相关参数**（服务器端）：降低 ZFIT 对低温边界的敏感度，或切换到适用于更低温度的原子数据表
2. **对输入 TIIN 做最小值裁剪**：在写入 inone 前将 Ti edge 裁剪到 >0.1 keV（会损失物理精度，仅作为 workaround）
3. **更新 ONETWO 的 ADAS 原子数据**：使用覆盖更低温度范围的数据文件（需 ONETWO 源码和 Fortran 编译环境）
4. **接受现状**：NN 剖面拟合链路已验证到 Namelist 写入阶段，ONETWO 兼容性留待后续与 ONETWO 维护者协调解决
