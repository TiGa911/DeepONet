# ProfileNet 使用说明书

## —— EAST 等离子体剖面拟合的神经网络替代方案

---

## 一、系统概述

### 1.1 解决的问题

EAST 托卡马克的 ONETWO 输运计算需要将离散的诊断测量点（汤姆逊散射 TS、反射计 Refl、X 射线晶体谱仪 TXCS）转换为 201 点的平滑径向剖面。现有方法使用 `fitting_mtanh.py` 中的 **mtanh + spline 参数化拟合**（约 800 行手工调参物理代码），包含 L/H 模分支、最小二乘台基优化、Savitzky-Golay 滤波等复杂逻辑。

**ProfileNet** 将此步骤替换为一个小型神经网络（~50K 参数），学习 "离散散点 → 平滑剖面" 的映射关系，训练标签由现有 mtanh 拟合器自动生成。推理耗时 < 1ms（vs 原有 ~0.5s），且无需手工调参。

## 二、网络架构

### 2.1 总体设计：DeepONet 风格

系统采用 **DeepONet（深度算子网络）** 架构，天然适合"函数 → 函数"的映射任务。核心思想是将网络分为两个子网络，最后通过点积融合：

```
输入：{(ρ₁, y₁), (ρ₂, y₂), ..., (ρₙ, yₙ)}  ← 来自诊断的 N 个离散散点（N 不固定）
                              │
                ┌─────────────┴─────────────┐
                │                           │
          ┌─────▼──────┐            ┌───────▼──────┐
          │  Branch Net │            │   Trunk Net  │
          │ (SetEncoder)│            │(CoordDecoder)│
          │             │            │              │
          │ 每个散点    │            │ 每个输出坐标 │
          │ (ρ, y) → MLP│            │ ρⱼ → MLP     │
          │ → 全局最大池│            │ → b(ρⱼ)      │
          │ → 隐向量 z  │            │   基函数      │
          └──────┬──────┘            └───────┬──────┘
                 │                           │
                 │     z · b(ρⱼ) = yⱼ       │
                 └───────────┬───────────────┘
                             │
                    ┌────────▼────────┐
                    │   Softplus      │  ← 保证输出 > 0
                    └────────┬────────┘
                             │
        输出：{y(ρ₁), y(ρ₂), ..., y(ρ₂₀₁)}  ← 均匀 rho 网格上 201 点平滑剖面
```

### 2.2 核心模块详解

#### SetEncoder（分支网络）

```
MLP(2 → 64 → 128 → 128)，每层 ReLU 激活
→ 全局最大池化（Max Pooling over points）
→ 输出固定长度隐向量 z ∈ R¹²⁸
```

- **设计要点**：借鉴 PointNet 的置换不变性思想。每个 (ρ, y) 点独立通过共享 MLP，再由全局最大池化聚合成定长向量。这使得网络可以处理**任意数量**的诊断输入点（TS 约 20-25 点，Refl 约 15-20 点，TXCS 仅 3-15 点）。
- **变长处理**：训练时将每个 batch 内样本 padding 到相同长度，配合 boolean mask 使池化忽略填充位置。

#### CoordDecoder（主干网络）

```
MLP(1 → 128 → 128)，SiLU 激活
输入：标量坐标 ρⱼ ∈ [0, 1]
输出：基函数向量 b(ρⱼ) ∈ R¹²⁸
```

- **设计要点**：SiLU（Sigmoid Linear Unit）作为激活函数，其平滑性优于 ReLU，能产生更光滑的基函数。坐标作为输入保证了输出剖面在 ρ 空间中的**平滑性与连续性**。

#### 输出 = z · b(ρ)（点积融合）

这是 DeepONet 理论的核心——分支网络的隐向量 z 编码了"输入散点的整体形状"，主干网络的基函数 b(ρ) 提供了"在坐标 ρ 处的展开基底"，两者点积即为最终预测值。最后经 Softplus（光滑版 ReLU）保证输出为正。

### 2.3 Ti 网络的特化设计

Ti（离子温度）网络 `ProfileNet_Ti` 具有**双编码器结构**：

```
TXCS 散点 ──→ SetEncoder ──→ z_txcs ──┐
                                        ├──→ Fusion MLP ──→ z ──→ 输出
Te 台基数据 ──→ SetEncoder ──→ z_ped  ──┘   (256→128→128)
 (ρ≥0.88)
```

**设计理由**：TXCS 的 Ti 测量点通常非常稀疏（仅 3-15 个有效通道），尤其在台基区域几乎没有数据。原始物理拟合利用 Te 台基（ρ ≥ 0.88 的 Te 剖面）作为 Ti 外推的边界条件。网络通过独立编码 Te 台基数据，再经 Fusion MLP 与 TXCS 特征融合，复现了这一物理依赖。

### 2.4 物理约束损失函数

训练使用的损失函数是四项的加权和：

```
L = L_MSE + λ₁·L_mono + λ₂·L_bdy + λ₃·L_smooth
```

| 损失项 | 公式 | 权重 | 物理意义 |
|--------|------|------|---------|
| L_MSE | ‖y_pred − y_true‖² | 1.0 | 数据保真度，拟合训练标签 |
| L_mono | mean(ReLU(dy/dρ)) | 0.1 | 惩罚"上翘段"，强制单调递减 |
| L_bdy | mean((dy/dρ)²) for ρ<0.05 | 0.5 | 磁轴处导数≈0（轴对称对称性） |
| L_smooth | mean(|d²y/dρ²|) | 0.05 | 惩罚二阶导大值，防止锯齿振荡 |

**关键细节**：
- L_mono 使用 `ReLU` 而非绝对值——**只惩罚正值导数（递增段），不惩罚正常的递减**。
- L_bdy 仅在 ρ < 0.05 区域计算，对应托卡马克磁轴附近的物理对称条件。
- Softplus 输出层保证了正定性（硬约束），无需额外损失项。

## 四、直接使用 API（无需完整 ONETWO 流程）

如果只想用神经网络替代剖面拟合部分，可以直接调用推理接口：

```python
import numpy as np
from profile_nn.infer import nn_fit_te, nn_fit_ne, nn_fit_ti, set_model_dir

# 指定模型目录
set_model_dir('./profile_nn_models')

# ===== Te 拟合 =====
rho_ts = np.array([0.1, 0.2, 0.35, 0.5, 0.7, 0.85, 0.92, 0.98])  # TS 测量点
te_eV  = np.array([3500, 3400, 3100, 2800, 2100, 1500, 800, 300]) # 原始 eV
rho_201, te_keV = nn_fit_te(rho_ts, te_eV)
# rho_201: (201,) 均匀网格
# te_keV:  (201,) Te 剖面 [keV]

# ===== ne 拟合 =====
rho_refl = np.array([0.05, 0.2, 0.4, 0.6, 0.8, 0.9, 0.95])
ne_1e19  = np.array([5.2, 5.0, 4.6, 4.0, 3.2, 2.5, 1.8])
rho_201, ne_201 = nn_fit_ne(rho_refl, ne_1e19)
# ne_201: (201,) 密度剖面 [1e19 m⁻³]

# ===== Ti 拟合（需要 Te 台基数据）=====
rho_txcs = np.array([0.15, 0.3, 0.5, 0.7, 0.85])   # TXCS 测量点
ti_keV   = np.array([2.1, 2.0, 1.8, 1.4, 0.9])      # Ti 值 [keV]
# Te 台基（ρ ≥ 0.88 区域的 Te 剖面值）
te_ped_x = np.array([0.88, 0.92, 0.96, 0.98])
te_ped_y = np.array([1.2, 0.8, 0.4, 0.2])
rho_201, ti_201 = nn_fit_ti(rho_txcs, ti_keV, te_ped_x, te_ped_y)
# ti_201: (201,) Ti 剖面 [keV]，已强制单调递减

# 所有三模型输出均经过 PCHIP + np.minimum.accumulate 保证严格单调递减
```

## 六、参数调优指南

### 6.1 什么时候需要调优

| 现象 | 调什么 | 方向 |
|------|--------|------|
| 芯部拟合差（ρ < 0.3 误差大） | `--epochs` | 增加到 1000 |
| 输出曲线有上翘段（非单调） | `--w-mono` | 从 0.1 → 0.5 甚至 1.0 |
| ρ = 0 附近导数明显不为零 | `--w-bdy` | 从 0.5 → 1.0 |
| 输出有锯齿状高频振荡 | `--w-smooth` | 从 0.05 → 0.2 |
| 台基区域偏差大 | 增加训练数据中 H 模样本比例 | 多跑几炮 H 模放电 |
| 内存不足 | `--batch-size` | 降至 16 或 8 |

## 七、常见问题

**Q: 需要 GPU 吗？**  
A: 不需要。模型仅 ~50K 参数，CPU 训练 500 epochs 约 5-10 分钟。

**Q: 训练数据需要多少？**  
A: 每类至少 500 样本起步，2000+ 可获得稳定结果。一炮 EAST 数据通常可产生 20-100 个有效时间片（取决于 TS 时间分辨率）。

**Q: 可以只训练部分诊断吗？**  
A: 可以。`--datatype Te` 只训练 Te，不影响 ONETWO 流程（但 Ti 依赖 Te，如果只训练 Ti 需要先有 Te 模型）。

**Q: NN 输出的剖面会违反物理吗？**  
A: 三层保护：(1) Softplus 输出层保证正定性；(2) 单调性损失在训练时正则化；(3) 推理后 PCHIP + `np.minimum.accumulate` 强制严格单调递减。三模型（Te/ne/Ti）输出均保证 >0 且严格非递增。

**Q: 如何对比 NN 和原始 mtanh 的效果？**  
A: 跑同一炮号分别用五个 pipeline（`onetwo_output.py` / `onetwo_output_nn.py` / `onetwo_output_lstm.py` / `onetwo_output_cnn.py` / `onetwo_output_transformer.py`），然后用 `python compare_profiles.py <shot> <time>` 自动提取各方法 TEIN/ENEIN/TIIN 并绘制在同一张对比图上。详见第十二节。

**Q: 遇到 `TXCS_EAST ERROR` 或 `zeff_error` 怎么办？**  
A: 这是**非致命错误**。TXCS_EAST 表示该时间点无 Ti 数据（TXCS 时间分辨率低于 TS，部分时间点缺失），管道会设置 `TXCS_status=0` 跳过 Ti 拟合，Te 和 ne 正常处理。`zeff_error` 表示 Brem_EAST Zeff 数据不可用，同样不影响 Te/ne。最终 `compare_profiles.py` 对比 TEIN/ENEIN 仍可正常进行。

**Q: 遇到 `No gfile found for shot X near time Y` 怎么办？**

## 九、LSTM 对照组模型

### 9.1 为什么需要 LSTM 对照组

ProfileNet 的 SetEncoder（PointNet 风格）具有**排列不变性**——交换任意两个散点的顺序不改变输出。这对于无序点云（如激光雷达）是优势，但对于**径向有序的等离子体剖面**（ρ = 0 芯部 → ρ = 1 边界），排列不变性反而丢失了空间序列信息。

**LSTM Baseline** 通过将 (ρ, y) 散点按 ρ 排序后送入双向 LSTM，显式建模径向序列结构，作为 ProfileNet 的对照组：

| 特性 | ProfileNet | LSTM Baseline | CNN-1D Baseline | Transformer Baseline |
|------|-----------|---------------|-----------------|---------------------|
| 编码器 | SetEncoder (PointNet) | BiLSTM (双向序列) | 1D ConvNet (扩张卷积) | TransformerEncoder (自注意力) |
| 排列不变 | ✅ 是（不关心顺序） | ❌ 否（依赖 ρ 排序） | ❌ 否（网格顺序固定） | ❌ 否（依赖 ρ 排序） |
| 径向结构感知 | 间接（从 ρ 坐标值推断） | 直接（LSTM 捕获相邻点关系） | 直接（卷积核提取局部模式） | 直接（自注意力捕获全局关系） |
| 参数量 | Te/ne ~58K, Ti ~133K | Te/ne ~68K, Ti ~124K | Te/ne ~47K, Ti ~109K | Te/ne ~127K, Ti ~246K |
| 共享解码器 | ✅ CoordDecoder | ✅ CoordDecoder | ✅ CoordDecoder | ✅ CoordDecoder |
| Te val loss (V1) | 0.370 | **0.325** ✓ | 0.806 | 0.367 |
| ne val loss (V1) | 0.376 | **0.358** ✓ | 1.056 | 0.373 |
| Ti val loss (V1) | **0.149** ✓ | 0.152 | 0.286 | 0.162 |

### 9.2 LSTM 架构详解

```
输入：{(ρ₁, y₁), (ρ₂, y₂), ..., (ρₙ, yₙ)}  散点（任意顺序）
                    │
            ┌───────▼───────┐
            │  按 ρ 排序    │   ← 从芯部到边界形成有序序列
            └───────┬───────┘
                    │
            ┌───────▼───────┐
            │ 2 层 BiLSTM   │   ← 双向捕捉前后上下文
            │ hidden=64     │
            └───────┬───────┘
                    │
            ┌───────▼───────┐
            │ h_forward ⊕   │  ← 拼接最后时间步的前向+后向隐状态
            │ h_backward    │
            └───────┬───────┘
                    │
            ┌───────▼───────┐
            │  Linear 投影  │  z ∈ R⁶⁴
            │ 128 → 64      │
            └───────┬───────┘
                    │
     ┌──────────────┼──────────────┐
     │              │              │
     │   z · b(ρⱼ)  │  ← 与 ProfileNet 共用的 CoordDecoder + 点积
     │              │
     └──────┬───────┘
            │
     ┌──────▼──────┐
     │  Softplus   │  ← 保证输出 > 0
     └──────┬──────┘
            │
输出：201 点平滑剖面 [keV] 或 [1e19 m⁻³]
```

**关键设计决策**：
- **排序**：推理时在 LSTM 内部按 ρ 排序，因此调用方无需关心输入顺序。`pack_padded_sequence` 处理变长序列，配合 mask 忽略填充点
- **BiLSTM**：双向 LSTM 让每个位置都能"看到"前后的诊断点，比单向 LSTM 更好地建模径向相关性
- **共享 CoordDecoder**：LSTM 与 ProfileNet 使用相同的 CoordDecoder 架构（MLP 1→128→128, SiLU），确保比较的公平性——差异仅来自编码器选择
- **Ti 双编码器**：`LSTMProfileNet_Ti` 同样具有 TXCS + Te 台基两组 BiLSTM 编码器，经 Fusion MLP 融合，对应 ProfileNet_Ti 的双 SetEncoder 设计

## 十、CNN 对照组模型

### 10.1 为什么需要 CNN 对照组

ProfileNet 用 SetEncoder（逐点 MLP + 最大池化），LSTM 用 BiLSTM 序列编码。两者都直接从散点提取特征。**CNN-1D** 提供了第三条路径：将散点线性插值到固定网格（64 点），然后用一维卷积提取多尺度径向特征。

四种编码器覆盖了「点集 → 隐向量」的主要建模范式：

| 特性 | ProfileNet | LSTM | CNN-1D | Transformer |
|------|-----------|------|--------|-------------|
| 编码器 | SetEncoder (PointNet) | BiLSTM | 1D ConvNet | TransformerEncoder |
| 输入形式 | 散点集（无序） | 排序序列 | 固定网格插值 | 排序序列 |
| 排列不变 | ✅ | ❌ | ❌（网格顺序固定） | ❌（依赖 ρ 排序） |
| 径向结构感知 | 间接 | 直接（序列） | 直接（卷积核） | 直接（全局自注意力） |
| 局部光滑性 | 弱（需靠损失约束） | 中 | 强（卷积天然平滑） | 中 |
| 多尺度特征 | 无（逐点处理） | 有（双向上下文） | 有（扩张卷积） | 有（多头注意力） |
| 参数量 | Te/ne ~58K, Ti ~133K | Te/ne ~68K, Ti ~124K | Te/ne ~47K, Ti ~109K | Te/ne ~127K, Ti ~246K |
| 共享解码器 | ✅ CoordDecoder | ✅ CoordDecoder | ✅ CoordDecoder | ✅ CoordDecoder |

> **公平比较设计**：四种模型共享相同的 CoordDecoder（MLP 1→128→128, SiLU）+ 点积融合 + Softplus 输出层，以及相同的 PhysicsConstrainedLoss。**差异仅来自编码器选择**。

### 10.2 CNN-1D 架构详解

```
输入：{(ρ₁, y₁), ..., (ρₙ, yₙ)}  散点（任意顺序，任意数量）
                    │
            ┌───────▼───────┐
            │  线性插值     │   ← 散点 → 64 点均匀网格 (ρ, y)
            │  到 64 点网格 │
            └───────┬───────┘
                    │  (B, 64, 2)
            ┌───────▼───────┐
            │ Conv1d(2→32)  │   ← 初始特征提取, k=5
            │     ReLU      │
            ├───────────────┤
            │ Conv1d(32→64) │   ← 特征升维, k=5
            │     ReLU      │
            ├───────────────┤
            │ Conv1d(64→64) │   ← 扩张卷积, k=5, dilation=2
            │     ReLU      │     扩大感受野至芯部-边界
            ├───────────────┤
            │ AdaptiveAvg   │   ← 全局平均池化 → (B, 64)
            │   Pool1d      │
            ├───────────────┤
            │ Linear(64→128)│   ← 投影到隐空间 z ∈ R¹²⁸
            └───────┬───────┘
                    │
     ┌──────────────┼──────────────┐
     │   z · b(ρⱼ)  │  ← 与 ProfileNet/LSTM 共用的 CoordDecoder + 点积
     └──────┬───────┘
            │
     ┌──────▼──────┐
     │  Softplus   │  ← 保证输出 > 0
     └──────┬──────┘
            │
输出：201 点平滑剖面 [keV] 或 [1e19 m⁻³]
```

**关键设计决策**：

- **固定网格插值**：将变长散点 → 64 点均匀网格（线性插值），使 CNN 能处理任意数量的输入散点。64 点远小于 201 点输出（避免过拟合），远大于典型散点数（保留信息）
- **三层卷积 + 扩张**：前两层标准卷积提取局部特征，第三层 dilation=2 扩张卷积将感受野翻倍，捕捉芯部到边界的全局趋势
- **AdaptiveAvgPool1d**（非 MaxPool）：平均池化产生更平滑的隐向量，比最大池化更适合连续剖面拟合
- **共享 CoordDecoder**：CNN 编码器输出 z 后，使用与 ProfileNet/LSTM 完全相同的 CoordDecoder + 点积架构。这是公平比较的基础
- **无 BatchNorm**：移除了旧版 CNN1D 中的 BatchNorm1d（在 64 长度的剖面数据上统计不稳定），仅用纯卷积 + ReLU

## 十一、Transformer 对照组模型

### 11.1 为什么需要 Transformer 对照组

ProfileNet 用 SetEncoder（逐点 MLP + 最大池化），LSTM 用 BiLSTM 序列编码，CNN-1D 用卷积提取局部特征。**Transformer** 提供了第四种范式：通过**多头自注意力（Multi-Head Self-Attention）**让每个诊断测点直接关注所有其他测点，捕获全局径向相关性。

四种编码器覆盖了「点集 → 隐向量」的全部主流建模范式：

| 特性 | ProfileNet | LSTM | CNN-1D | Transformer |
|------|-----------|------|--------|-------------|
| 编码器 | SetEncoder (PointNet) | BiLSTM | 1D ConvNet | TransformerEncoder |
| 核心机制 | 逐点 MLP + 最大池化 | 双向递归序列 | 扩张卷积 | 多头自注意力 |
| 排列不变 | ✅ | ❌ | ❌ | ❌（依赖 ρ 排序） |
| 全局感受野 | ✅（池化后） | ❌（局部递归） | ❌（局部卷积核） | ✅（每个点 attend 所有点） |
| 计算复杂度 | O(N) | O(N) | O(N) | O(N²)（需随机子采样缓解） |
| 参数量 | Te/ne ~58K, Ti ~133K | Te/ne ~68K, Ti ~124K | Te/ne ~47K, Ti ~109K | Te/ne ~127K, Ti ~246K |
| 共享解码器 | ✅ CoordDecoder | ✅ CoordDecoder | ✅ CoordDecoder | ✅ CoordDecoder |

### 11.2 Transformer 架构详解

```
输入：{(ρ₁, y₁), (ρ₂, y₂), ..., (ρₙ, yₙ)}  散点（任意顺序）
                    │
            ┌───────▼───────┐
            │  按 ρ 排序    │   ← 从芯部到边界形成有序序列
            │  + 随机子采样 │   ← 若 N > max_len（Ti ~400 点），保留首尾 + 随机采样
            └───────┬───────┘
                    │  (B, N, 2)
            ┌───────▼───────┐
            │ Linear(2→64)  │   ← 投影到隐空间
            └───────┬───────┘
                    │  (B, N, 64)
            ┌───────▼───────┐
            │ + 可学习位置  │   ← 正弦式位置编码，支持动态插值到任意序列长度
            │   编码 (PE)   │
            └───────┬───────┘
                    │  (B, N, 64)
            ┌───────▼─────────────────────────┐
            │ TransformerEncoder ×2 layers    │
            │  · 4-head Multi-Head Attention  │  ← 每个点关注所有点（全局感受野）
            │  · FFN=256, GELU 激活           │
            │  · Dropout=0.1                  │
            │  · src_key_padding_mask 忽略填充 │
            └───────┬─────────────────────────┘
                    │  (B, N, 64)
            ┌───────▼───────┐
            │   Mean Pool   │   ← 对有效位置取平均 → z ∈ R⁶⁴
            │ (mask 加权)   │
            └───────┬───────┘
                    │
     ┌──────────────┼──────────────┐
     │   z · b(ρⱼ)  │  ← 与 ProfileNet/LSTM/CNN 共用的 CoordDecoder + 点积
     └──────┬───────┘
            │
     ┌──────▼──────┐
     │  Softplus   │  ← 保证输出 > 0
     └──────┬──────┘
            │
输出：201 点平滑剖面 [keV] 或 [1e19 m⁻³]
```

**关键设计决策**：

- **2 层 TransformerEncoder，4 头注意力**：与 LSTM 的 2 层 BiLSTM 深度对齐。4 个头允许模型从不同子空间关注径向结构（芯部-芯部、台基-台基、芯部-台基等）
- **可学习位置编码**：使用 `nn.Parameter(torch.randn(1, max_len, hidden) * 0.02)` 随机初始化，训练中优化。支持 `F.interpolate` 动态扩展到超过 max_len 的序列
- **随机子采样**：Ti 样本可达 400+ 散点，O(N²) 自注意力导致显存/计算爆炸。当 N > max_len 时，保留首尾点 + 随机采样 max_len−2 个中间点，每次前向传播采样不同（等效数据增强）
- **GELU 激活**：Transformer 标准激活函数，比 ReLU 在注意力机制中更平滑
- **Mean Pool（非 CLS token）**：对全部有效位置取 mask 加权平均作为序列表示，信息利用率高于单 token
- **Ti 双编码器**：`TransformerProfileNet_Ti` 同样具有 TXCS + Te 台基两组 TransformerEncoder，经 Fusion MLP(256→128→128) 融合

## 十二、五种方法剖面交叉对比

### 12.1 为什么需要交叉对比

单看验证损失（val loss）只能评估模型对 mtanh 标签的拟合精度，无法回答：
- NN 拟合的剖面与原始 mtanh 剖面在 ONETWO 输入层面有多大差异？
- 差异集中在哪个径向区域（芯部 / 台基 / 边界）？
- 三个 NN 方法之间谁更接近 mtanh 基线？

`compare_profiles.py` 自动化这一对比过程，在同一炮号同一时间点下，从五个 pipeline 的 `inone` 输出文件中提取 **TEIN / ENEIN / TIIN** 剖面，绘制在同一坐标轴上，并计算定量偏差。

### 12.2 前提条件

同一炮号的同一时间点下**至少跑了两个 pipeline**，其中一个建议是 mtanh 原始版（作为基线）：

```bash
# 在服务器上，依次跑五个 pipeline（互不覆盖）
python3 onetwo_output.py              # → onetwo/             (mtanh 基线)
pytorch_run onetwo_output_nn.py       # → onetwo_nn/          (ProfileNet)
pytorch_run onetwo_output_lstm.py     # → onetwo_lstm/        (LSTM)
pytorch_run onetwo_output_cnn.py      # → onetwo_cnn/         (CNN-1D)
pytorch_run onetwo_output_transformer.py  # → onetwo_transformer/ (Transformer)
```

> 如果某些方法未跑，对比脚本会自动跳过，不会报错。

### 12.3 使用方法

```bash
# 方式 1：单时间点对比（命令行传参）
python compare_profiles.py 81481 5.3

# 方式 2：单时间点对比（交互式输入）
python compare_profiles.py
# Shot number: 81481
# Time (s): 5.3

# 方式 3：批量模式 — 自动扫描该炮所有含 inone 文件的时间点
python compare_profiles.py 81481 --batch

# 方式 4：批量模式 — 只生成汇总 CSV，跳过逐时间点 PNG
python compare_profiles.py 81481 --batch --csv-only
```

**单时间点模式**：程序自动定位 `results/{shot}/` 下与目标时间最接近的目录，读取各子目录中的 `inone` 文件，生成对比图和指标文件。

**批量模式**（`--batch`）：程序扫描 `results/{shot}/` 下所有时间点目录，自动发现哪些时间点下存在 `inone` 文件（任意方法），然后逐一生成对比结果。最终生成：

- `results/{shot}/{time}/compare/` — 每个时间点的对比图 + 指标文件（与单时间点模式相同）
- `results/{shot}/compare_summary.csv` — 全部时间点汇总表，包含每时间点每方法每诊断的 MAE/RMSE/MaxAE

### 12.8 注意事项

1. **网格对齐**：各方法的 RTEIN/RENEIN/RTIIN 网格都是 201 点 `linspace(0, 1, 201)`，但若某方法使用了不同网格，对比脚本会自动用线性插值对齐到 mtanh 的网格
2. **单位一致性**：对比脚本读取的是 `inone` 文件中实际写入的值（TEIN=eV, ENEIN=cm⁻³, TIIN=keV），与 ONETWO 求解器看到的值完全一致
3. **缺少基线**：如果没跑 mtanh 版本，左栏仍会叠加所有可用方法的剖面，但右栏差值图和 `compare_metrics.txt` 将跳过
4. **`compare_profiles.py` 不依赖 PyTorch**，可以在服务器上用普通 `python3` 运行（不需要 `pytorch_run` 前缀）
